## Notes

**The idea.** A static site that displays skill trees for real-life domains
(grant-writing, ethnomusicography, stand-up comedy, more later). Trees are
generated by the Mr. KTG two-pass prompt ([ktg-prompt.md](../ktg-prompt.md) —
the canonical frame; the JSON schema there is the data contract). Game-like
UX, read-only.

**Vocabulary** (from the KTG frame — use these words exactly): *domain* (one
tree), *node* (one skill, 5–60 hours, pass/fail *checkpoint*), *tier*
(1 + max tier of hard prereqs), *cluster* (named group with a *gist*),
*spine* (8–12-node shortest path to competence), *school* (a camp with
optimises_for / gives_up / quarrels_with), *school_weights*
(high/normal/low/rejected per node), hard *prereqs* (≤3) vs *soft_prereqs*.

**Decisions from the charting interview:**

- Core loop: **read-only atlas** — no personal progress state. Progress
  tracking was explicitly *not* chosen as a future to design for.
- Pipeline: KTG runs by hand in any LLM chat; output is **committed JSON**
  under the repo; a **build-time validator** enforces the graph rules so a
  bad paste cannot ship. The site knows nothing about LLMs.
- Visual form: **tiered tech-tree** — tiers as columns, clusters as colored
  lanes, spine as the golden path, soft prereqs as faint dashed edges.
- Stack: **Astro** builds one static page per domain from the JSON; the tree
  is a hand-rolled **SVG renderer in a plain TypeScript module**.
- Node bodies open in a **side panel**; the tree stays visible and the
  prereq chain highlights.
- **School lens** is the signature interaction: pick a school, nodes re-tint
  by weight (high glows, low dims, rejected struck through).
- Leave architectural room for: **cross-domain links**, **route planning**
  (graph utilities separate from rendering), **community trees via PR**
  (strict validator + contributor docs).

**Skills to consult:** /prototype for prototype tickets, /grilling and
/domain-modeling for grilling tickets.

**Tracker conventions (local markdown):** each ticket is a file in this
directory with frontmatter — `status: open|closed`, `assignee` (the claim;
null = unclaimed), `blocked-by` (list of ticket files). Frontier = open,
unassigned, all blocked-by tickets closed. Resolution comment goes at the
bottom of the ticket file under `## Resolution`.

- [On-disk data layout for domains](001-data-layout.md) — skeleton.json +
  bodies/*.json per domain, merged at build; skeleton required & sufficient to
  ship, bodies lazy in batches; regeneration replaces the skeleton only, diff

- [URL & ID scheme](004-url-id-scheme.md) — id contract accepted as-is from the
  frame (`domain.cluster.node`, stable forever; cluster moves are explicit id
  changes the stability diff flags); routes: `/` index, `/<domain-slug>` tree
  page, `?node=<full id>` deep link opening the side panel — the shape
  cross-domain links reuse later.
- [Pilot domain — generate the grant-writing tree](003-grant-writing-tree.md) —
  real dataset landed: 51-node grant-writing skeleton + 14 bodies (11 spine
  batch + 3 follow-up, spine reworked to an honest 5-node chain); verified
  clean; cadence = spine-first lazy (deferral is optionality); findings +
  validator suggestions in pilot-notes.md.
- [Contribution workflow for community trees](009-contribution-workflow.md) —
  both paths (PR as path of record, issue fallback for domain experts);
  review promise = validator-pass is enough, no human content step;
  regeneration open to anyone, guarded by the id-stability diff, no
  provenance file.
- [Validator — the data contract as code](002-validator.md) — zero-dep
  scripts/validate.mjs + package.json scripts; full error/warning surface per
  layer, batch envelope ids contract, stability mode; verified on real data
  (0 errors), broken-tier fixture, and drift fixture. Spine length is a
  calibration warning and spine gaps an error (transitive closure) — the
  frame's 8–12 spine target is arithmetically impossible in ≤6-tier mesh
  domains.
- [Tree renderer prototype](005-tree-renderer-prototype.md) — throwaway at
  prototypes/tree-renderer/ (3 variants, verified in browser); decisions:
  tiered columns + cluster lanes, left-to-right beziers, soft edges dashed
  default-on, spine as its own gold path layer, label-on-node + tooltip,
  DOM-free graph.js seam for route planning. Exposed the gapped spine (fixed).
- [School lens semantics](007-school-lens.md) — throwaway at

## Fog

- **Route planning** — pick a target node, highlight the prereq path, sum
  hours. The renderer now exists and the graph/drawing seam is decided:
  src graph utilities are DOM-free (topo, ancestors/descendants, edges) and
  reusable wholesale. Building the feature itself is deliberate future scope
  — the map leaves room for it, nothing blocks it.
- **Cross-domain links** — nodes referencing nodes in other domains
  (ethnomusicography → audio engineering). The URL half is settled (absolute
  `/<domain>?node=…` links work). What remains: the KTG frame has no syntax
  for cross-domain references — needs a schema extension — and 2+ real domains
  to link. Hangs on the pilot and on the schema question.
- **Atlas index** — the home page: how many domains before it needs real
  discovery/browsing design rather than a list. Hangs on seeing 3+ domains.
- **More domains** — ethnomusicography and stand-up comedy generation. The
  pipeline is now proven (skeleton → loud check loop → spine bodies first),
  so a new domain is a known recipe, not open design. Generating them is
  deliberate future scope — no open questions block it. The BODIES cadence
  decision is made (spine-first lazy).
- **Game-feel polish** — sound, animation on hover, theming per domain.
  Deliberately vague until the renderer prototype sets the base aesthetic.
